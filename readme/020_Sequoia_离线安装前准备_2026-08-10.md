# Sequoia 15.7.9 离线安装前准备（2026-08-10）

**本文档管什么**：安装介质、硬件前提与上机前检查。
实际成功的安装过程和菜单选择见 `030_Sequoia_15.7.9_离线安装过程与关键选择_2026-08-13.md`；进入桌面后的配置见 `040_装机后配置与待办_2026-08-13.md`。

---

## 1. 安装介质准备

### 1.1 制盘前确认

- Linux 制作机上安装 `hfsprogs`、`dosfstools`、`gdisk`。
- **每次写盘前重新确认设备名**：2026-08-10 实测 `sdb` 为 Netac OnlyDisk 58G U 盘，`sda` 为制作机系统盘；设备名会变化，不能照抄。
- U 盘分为两个分区：

  | 分区 | 格式/卷标 | 内容 |
  |---|---|---|
  | `sdb1` | FAT32 / `OPENCORE` | `EFI/` 与 `com.apple.recovery.boot/` |
  | `sdb2` | HFS+ / `MACDATA` | `InstallAssistant.pkg` 与 `UnPlugged.command` |

> 本文已成功验证的是 HFS+ 数据分区；当时测试的 exFAT 分区挂载失败，但不足以证明所有 Recovery 环境都不支持 exFAT。FAT32 在本方案中仅承载 EFI 和 Recovery 文件。

### 1.2 写入后检查

`MACDATA` 中的 `InstallAssistant.pkg` 必须与源文件逐字节一致；本次制作的校验结果为 `PKG_OK`。
同时确认 `UnPlugged.command` 可读取，`InstallAssistant.pkg` 完整存在。

Linux 向 FAT32 写入时，`cp -a` 可能报无法保留 ownership；Linux 挂载 HFS+ 后，`ls` 也可能报 `No data available`。两者均属文件系统元数据限制；应以目录内容、文件大小和 `cmp` 校验结果判断写入是否成功。

大文件的 `cp`、`cmp`、`sync` 在慢速 U 盘上耗时很长。进程仍有 I/O 时不要中断。

## 2. 上机前硬条件

1. 内置 NVMe 已安装散热片、导热硅脂，且有小风扇直吹主板。
2. 从 Linux 启动环境运行 `nvme smart-log /dev/nvme0`：`media_errors` 和 `critical_warning` 必须为 0；同时记录 `temperature`、`warning_temp_time`、`unsafe_shutdowns` 作为基线。
3. 机箱或裸板周边保持通风，风扇已通电。
4. 准备 OBS 录屏。panic 和安装报错信息可能短暂刷过，录屏便于复核。

> 旧 NVMe 曾在持续写入后从设备列表消失；更换硬盘后本次安装成功。两者相关，但现有证据不足以确认唯一故障机理，详见 `010_Hackintosh_Sequoia_EFI配置说明_2026-08-09.md`。

---

## 3. 上机前接线与进入点

- 网线接路由器 **LAN** 口，不接 WAN，也不做机对机直连。
- 为复现本次成功路径，U 盘和键鼠分别直插 USB-A 口；当时使用的 Hub 下键鼠无响应，不代表所有 Hub 均不可用。
- 开机后在 OpenCore 菜单进入 `macOS Base System` / `Recovery`。
- 进入 Recovery 后，从 `030_Sequoia_15.7.9_离线安装过程与关键选择_2026-08-13.md` 第 1 节继续执行。

安装全程保留 U 盘，直至 macOS 安装完成并进入桌面。
