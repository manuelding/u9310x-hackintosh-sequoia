### 1.2 EFI 已装到内置盘（拔 U 盘可独立启动）

安装完成后系统本体在内置盘，但 OpenCore 仍只在 U 盘上——不搬过去，拔掉 U 盘就报
`Bootable device was not found`。

本机分区对照（`diskutil list` 实测）：

| 标识 | 卷名 | 说明 |
|---|---|---|
| `disk0s1` | `EFI` | **内置 NVMe 的 ESP**（209.7 MB，FAT32） |
| `disk0s2` | — | APFS 容器，内含 `Macintosh HD` |
| `disk2s1` | `OPENCORE` | U 盘 ESP |
| `disk2s2` | `MACDATA` | U 盘 HFS+ 数据分区 |

> 两个 ESP 卷名不同（`EFI` vs `OPENCORE`），不会出现 `EFI 1` 歧义；仍应先 `ls` 确认再复制。

在 macOS 桌面里执行（U 盘保持插着）：

```bash
sudo diskutil mount disk0s1 && sudo diskutil mount disk2s1
ls -la /Volumes/EFI /Volumes/OPENCORE
sudo cp -R /Volumes/OPENCORE/EFI /Volumes/EFI/
ls -l /Volumes/EFI/EFI/BOOT/BOOTx64.efi /Volumes/EFI/EFI/OC/OpenCore.efi /Volumes/EFI/EFI/OC/config.plist
```

最后一条必须三个文件全部列出（实测 24 KB / 631 KB / 30 KB）才算成功。
然后：关机 → 拔 U 盘 → BIOS 把内置 NVMe 排到启动顺序第一位 → **Secure Boot 保持关闭** → 重启。

若 BIOS 仍找不到启动项：确认 `\EFI\BOOT\BOOTx64.efi` 存在（UEFI 通用回退路径），
必要时在 BIOS 里手动 Add Boot Option 指向该文件。

### [x] TODO-4　USB 端口映射（`USBToolBox` / `UTBMap`）　✅ 2026-08-13 完成

**做法：没有用 USBToolBox 工具跑 TUI，而是手工实测端口 + 按上游源码格式直接生成 kext。**

原因：上游工具在 macOS 下需要 `pyobjc` + `termcolor2` + `ansiescapes`（最后一个只能从 GitHub
用 git 装），依赖链在这台机器上太长；而且**上游 README 明确说不推荐在 macOS 上做映射**
（拿不到端口类型猜测与伴生端口绑定）。既然只有 5 个端口，逐口物理插拔实测比工具推断更可靠。

> ⚠️ `010` 第 3.3 节写的「在 macOS 里做 mapping 比在 Windows 下准确」**与上游说法矛盾**。
> `010` 中“在 macOS 里更准确”的旧表述已删除。后续以 USBToolBox 当前上游说明和目标机逐口实测为准。

#### 实测端口表（每一格都有物理插拔证据，无一推断）

控制器：`AppleUSBXHCI @ 0x14000000`，PCI `8086:02ed`（CML-U PCH），**ACPI 名 `XHC`**（唯一，用作 `IONameMatch`）

| 映射名 | 原始端口 | UsbConnector | 物理位置 | 实测依据 |
|---|---|---|---|---|
| `HS01` | 1 | 3 (USB3 Type-A) | **LAN 口** USB2 personality | Netac OnlyDisk → `0x14100000` |
| `HS02` | 2 | 3 (USB3 Type-A) | **HDMI 口** USB2 personality | 罗技接收器 → `0x14200000`，拔插验证 |
| `HS03` | 9 | **255 (Internal)** | 板载 Genesys Logic hub | `0x14900000`，空载，拔外设不消失 |
| `SS01` | 13 | 3 (USB3 Type-A) | **LAN 口** SuperSpeed | Fanxiang F302 → `0x14d00000`，5 Gb/s |
| `SS02` | 14 | 3 (USB3 Type-A) | **HDMI 口** SuperSpeed | Fanxiang F302 → `0x14e00000`，5 Gb/s |

`port-count` = 14。

**Type-C ×2 不进映射表**：一个被电源占用，另一个无反应。根本原因是它们挂在
TB3 控制器 `JHL7540` 上，而该控制器**在 macOS 下完全没有枚举**——
`system_profiler` 里自始至终只有 `8086:02ed` 一条 USB 总线。
控制器都不存在，就没有端口可映射。**这不是 macOS 不支持 USB-C**，
是这块板的 TB3 控制器在 macOS 下没上电。`010` 1.3「按没有规划」得到实证。

#### ★ 映射生效后 locationID 会重新编号（重要，别被吓到）

映射生效后，未列入表中的端口被裁掉，**保留的端口按映射表里的位置序重新编号 1..N**，
所以 locationID **不再等于原始端口号**：

| 位置序 | 映射名 | 原始端口 | 生效后 locationID |
|---|---|---|---|
| 1 | `HS01` | 1 | `0x14100000` |
| 2 | `HS02` | 2 | `0x14200000` |
| 3 | `HS03` | 9 | `0x14300000` |
| 4 | `SS01` | 13 | `0x14400000` |
| 5 | `SS02` | 14 | `0x14500000` |

五格全部经过插拔实测验证，一一对应。

- 裸板形态下**永久放弃**：电池管理、内屏亮度/光感、内建键盘触控板

**症状**：远程看不到鼠标指针，但**盲点可以正常操作**，右键菜单会正常弹出；重启后依旧，接收器插回去也依旧。

**已确认不是 USB 映射引起的**：能盲点出右键菜单 → HID 事件正常送达，输入链路完好。USB 映射管的是设备识别、供电、睡眠唤醒，**管不到指针画不画得出来**——指针渲染归 WindowServer/图形栈，两条不同的路。

**待验证假设：VNC 客户端没有正确显示远程光标。** 这只是排查起点；TigerVNC 的剪贴板问题不能证明光标问题也由客户端造成。

验证顺序：

1. 换用 RealVNC Viewer，看指针是否出现。
2. 若仍不可见，放大指针判别是“没画”还是“画了但看不见”：
   ```bash
   defaults write com.apple.universalaccess mouseDriverCursorSize 3.0 && killall Dock
   ```
   放大后可见 → 客户端/采集侧的光标层问题；仍不可见 → 再排查系统侧。验完还原：
   ```bash
   defaults delete com.apple.universalaccess mouseDriverCursorSize && killall Dock
   ```

> 不要为这个去动 config.plist 或 kext —— 证据指向远程显示链路，不指向 OpenCore。
